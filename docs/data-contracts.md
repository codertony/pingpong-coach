# 数据契约

用途：坐标、单位、时钟、缺失值、schema 版本的**唯一说明**。
代码层的唯一来源是 `packages/contracts/`。本文件与代码不一致时，以代码为准并修正本文件。

## 数据链

```
PoseFrame → StrokeEvent → FeatureSet → EvidencePacket → CoachFeedback
```

## 时间和坐标（逐条）

1. **`sourceTimeMs`**：来自源视频媒体时间，统一为毫秒。导入视频以媒体时间为准，**不能**用播放耗时计算运动速度。
2. **`receivedAtMonoMs`**：浏览器收到帧时的单调时钟，用于处理耗时记录，不冒充相机曝光时间。
3. **`sourceEpoch`**：对视频 seek、重播、切换摄像头时递增，并重置跟踪/分段状态，保证向姿态引擎提供的时间符合其约束。
4. **不直接用浏览器和服务端两个独立时钟相减**。端到端耗时由浏览器计时，服务端记录自身处理时长。
5. **二维关键点先映射回原始画面像素坐标**。用归一化 x/y 计算角度前，必须分别乘原图宽高，避免长宽比造成角度失真。
6. **记录图像旋转、裁剪和镜像变换**。镜像预览不能改变人体真实左右标签。
7. **原始画面坐标与身体相对坐标分开保存**：前者保留两点移动，后者用于肘相对躯干的变化。
8. **像素位移按本次标定尺度归一化后，不能标成真实厘米。**
9. **单目估计的三维坐标保留 estimate 标记**；不得与多摄像头标定结果混用。

### 长宽比失真有多严重（实测）

1280×720 画面中一个**真实的 60 度**肘角，若直接用归一化坐标计算，会得到约 **72.0 度**——误差 12 度，远大于 10 度的验收门槛。所以 `angleDegFromNormalized` 会强制先乘回原图宽高。

> 注意一个反直觉点：由水平边与竖直边构成的角，因为两条边各沿一个轴被独立缩放，比值不变，**不失真**。失真只出现在非轴向的角度上。

## 单位

| 单位 | 含义 | 禁止 |
| --- | --- | --- |
| `deg` | 二维夹角，180 表示伸直 | 不得当作三维关节角 |
| `ms` | 毫秒 | — |
| `px` | 画面像素 | 不得标为厘米 |
| `body_scale` | 按体尺度（肩中点—髋中点距离）归一化 | 不得还原为真实长度 |

## 坐标空间

| 值 | 用途 |
| --- | --- |
| `image_2d` | 原始画面像素坐标 |
| `body_relative_2d` | 相对躯干参考点、按体尺度归一化 |

## 缺失值规则

**任何未观察到的指标使用 `null` 和原因，不使用 0 填补缺失。**

0 是合法测量值，与"没测到"必须可区分。因此：

- `FeatureValue.value` 为 `null` 时，`reasonIfMissing` 必须给出可读原因。
- `quality` 同时标注该测量的可信程度。
- 契约层用 `z.number().nullable()` 而非默认 0。

## 质量状态

| 值 | 含义 | 下游行为 |
| --- | --- | --- |
| `usable` | 可用于数值判定 | 允许输出达标/调整结论 |
| `limited` | 可观察但不足以做精细判断 | 降级为 `observation_only` |
| `unusable` | 无法使用 | 明确拒绝给结论 |

对"看不清"和"确有动作偏差"使用**不同错误码**，分别统计。错误码清单见 `packages/contracts/src/primitives.ts`。

## 事件锚点命名纪律

锚点类型是 `wrist_speed_peak` 时：

- 指标必须命名为 `return_after_wrist_peak_ms`；
- **不得**使用 `recovery_after_impact_ms`；
- `StrokeEvent.impactTimeMs` 在可靠识别球拍接触球之前**始终为 `null`**。

## 版本

- `SCHEMA_VERSION = "1"`：破坏性字段变更时提升，并保留旧评估样本的解释能力。
- `RULE_VERSION`：规则集内容变更时提升，用于把历史反馈关联到当时的判定依据。
- 知识条目自带 `version` 与 `status`。

## 图片与请求预算

| 项目 | P1 初始限制 |
| --- | --- |
| 挥拍数量 | 默认 3 次有效挥拍 |
| 原始关键帧 | 最多 6 张，优先覆盖引拍、向前挥拍、还原 |
| 图片 | 按目标部位裁剪并保留必要身体背景；最长边不超过 960 像素 |
| 请求总大小 | 上限 2 MiB，超限先减少冗余图片并记录降采样 |
| 模型输出 | 上限约 400 tokens |
| 语音 | 单条不超过约 30 个汉字 |

**图片压缩导致目标关节不清晰时，必须降低该目标的可判性，不能为了满足大小预算继续给精细判断。**

## 数据落地策略

- 真实视频和含个人信息的派生数据保存在 **Git 之外**。
- 仓库保存：数据说明、脱敏清单、标注 schema、哈希与取得方式（见 `evaluation/samples.json`）。
- 没有素材时可以用合成坐标做计算测试，但**不能**据此声称真人识别通过。
- 每次反馈记录：session/group/focus/request ID、原始证据引用、源时间范围及图像变换、SDK/模型/规则/知识/提示词/schema 版本、采样质量与各段耗时、token 与费用（提供商可返回时）、超时与拒绝判断、用户评价与教练复核。
