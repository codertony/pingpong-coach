## 1. 设计（v2）

### 1.1 目标与边界（不变的部分）

固定机位、单人、定点正手攻球的小闭环。保持 MediaPipe 33 点作为**第一版测量底座**。
范围外的动作类型（反手、起下旋）**不要假装覆盖** —— 契约里 `StrokeType` 目前只有
`forehand_drive`，这是事实，不是遗漏。

### 1.2 分层：从像素到建议，每层各自可验收

v1 的分层是"采集 → 推理 → 分段 → 特征 → 证据 → 反馈"，v2 在中间**插入事件层**，
并把"标准"从提示词里拿出来、变成一等对象：

```
采集(帧+像素)  →  姿态点位  →  挥拍候选  →  阶段事件  →  逐板指标  →  与标准对照  →  解释与提示
                                    ↑                        ↑
                              不再以"还原达标"               审核后的参考模板
                              作为被看见的前提               与条件化规则
```

**每一层都能单独判定对错**，这是修订的核心：v1 的问题是"分段不对"会一路静默地
变成"模型讲得含糊"，而中间没有任何一层能被单独验收。

| 层 | 输入 | 输出 | 单独验收什么 |
| --- | --- | --- | --- |
| 挥拍候选 | 腕部轨迹 + 体尺度 | "这里发生了一次挥拍"（含起止） | 与人工标注比 precision / recall（tIoU ≥ 0.5） |
| 阶段事件 | 候选 + 点位时序 | 引拍末端 / 前挥 / 随挥末端 / 还原（**允许缺失**） | 事件时间误差 P50/P95；不可见事件**明确标缺失** |
| 逐板指标 | 阶段事件 + 点位 | 每板、每阶段的数值曲线与标量 | 数值可复算；缺失带原因 |
| 对照 | 逐板指标 + 匹配的参考 | 逐项偏差 + 替代解释 | 条件不匹配时**拒绝比较**，而不是硬比 |
| 解释 | 对照结果 + 证据 | 观察 + 逐条要点 + 一条提示 | 事实正确率 / 建议适用率（**要人读**） |

**"对照"这一层有一条分叉**（评审 §9）：证据够 → 逐项偏差；证据不够 →
**明说缺什么、要不要重拍**，而不是硬给一个结论。这条分叉是设计的一部分，
不是错误路径 —— 一个总在给结论的系统，恰恰是它不知道自己缺什么的信号。

### 1.3 把"还原"从"被看见"里解耦（R6，最重要的一条设计改动）

现在的状态机要求**回到准备区稳定驻留**才闭合一次挥拍。后果有两层：

1. 计数偏少（F-022 的合并）；
2. **最该被指出的动作恰恰不被看见** —— 没还原好的那一板，正是需要提示的那一板。

v2 的设计：**"发生了一次挥拍"与"这次是否完成目标还原"分成两件事**。
前者决定"要不要看这一板"，后者是这一板的**一个指标**。
实现上就是：给候选检出加一条**不依赖准备区**的通路（速度/位移/方向），
准备区只用于评价还原质量。

⚠️ 这会改变检出数量，**必须与人工标注一起验收**，不能只看"检出变多了"就上线 ——
变多也可能是把挥空和走动算了进来。

### 1.4 标准应该做成什么（R7）

**结论：不做"通用标准动作库"**（评审已核实：现有公开资料里没有一个能直接导入的）。
采用**教学文字 + 专业示范视频 + 结构化点位时序 + 条件化规则 + 错误案例**的混合标准包。

一个标准包的组成（评审 §5.2）：

| 层 | 内容 | 作用 |
| --- | --- | --- |
| 适用条件 | 技术类型、持拍手、来球旋转/高度/速度、站位、机位、示范速度 | **先决定是否可比** |
| 来源 | 文献/教学 URL、视频时间段、作者、审核人、日期、版本、许可 | 标准从哪来 |
| 教学描述 | 要点、原因、常见误解、适用水平、允许的个体差异 | 给人和模型理解 |
| 专业示范 | 原视频、帧时间戳、拍摄元数据、多次合格重复 | 保留视觉事实 |
| 结构化运动 | 点位轨迹、可见性、质量、阶段事件、角度与相对位置曲线 | 支持机器比较 |
| 判断规则 | 特征定义、可观察条件、参考范围、阈值来源、不可判条件 | 决定哪里要关注 |
| 错误与训练 | 已审核的问题片段、正常变体、对应提示与训练动作 | 把偏差转成行动 |

**四种来源必须分开，不能合成一个"标准分"**：
① 跨个体的技术原则 → ② 条件化参考范围 → ③ 教练确认的个人可行目标 → ④ 当前个人基线（只说明进步，**不证明正确**）。

关于第 ④ 条特别要说一句：**准备区是按用户自己的腕部分布自动标定的**。
它可以服务于跟踪，**不能**自然成为"正确准备姿势" —— 用户稳定地做错，也会得到稳定的基线。

### 1.5 关键帧：先定事件，再选图（R4）

两条结论要**分开验收**，不能混：

- **事件定位**：事件在哪个时间区间，误差多大；
- **展示关键帧**：区间内（或有明确偏移说明的邻近）清晰帧，用来看细节。

**不能为了挑清晰图而悄悄挪动事件时刻。** 选帧的约束（评审 §6.2）：

1. 候选 = 有像素 ∧ 有姿态 ∧ 有时间戳的交集（**R3 已经这么做了**）；
2. 先限同一板、同一事件窗；跨窗即报缺失，**不借另一板的图**；
3. 窗内比清晰度、相关关节可见性、人体像素尺度、遮挡；
4. 组级预算优先"一板典型 + 一板代表性偏差"，**不是每板硬发 6 张**；
5. 全身 + 手臂局部裁剪并存，裁剪**必须有原图坐标映射**，角度测量仍在一致坐标系完成；
6. 每张图标动作编号、阶段、源时间、距事件偏移、质量；提供逐帧前后切换。

| # | 状态 |
| --- | --- |
| 1 | ✅（R3）|
| 2 | ✅（F-058）：半开窗口 + 窗内取不到就报缺失，借窗外的图也不会借 |
| 3 | ❌ **只按"有没有图 / 离事件多近"挑，没有比清晰度与遮挡** —— 而"更清晰"要**独立标注**才知道（§6.2），自己定义一个清晰度分就是自造测量值 |
| 4 | ❌ **本批不做**（已与你确认）：要先定义"偏差"是**哪个量**上的偏差，那是 P3 对照层的事；现在编一个就是自造判据 |
| 5 | ❌ **未做，且不打算在收益验证前做**：坐标映射本身能写对，但多一份局部图是实打实的成本（图更多、2 MiB 预算更紧、提示词更吵），而"局部图让判断更准"同样要独立标注（§6.2）|
| 6 | 🟡 **部分**：板号／阶段／源时间／距事件偏移都进了契约与提示词（F-058）；**质量**同第 3 条；"逐帧前后切换"由复查页的按板回放部分覆盖（F-060）|

**不用生成式补帧/修复图作为测量依据** —— 它可能生成实际上不存在的球、手指或球拍位置。

#### 1.5.1 帧率分四列报告，导入按可控解码步长（评审 §6.3）

**"帧率"不是一件事，是四件事**，各自报告，谁也不能代替谁：

| 环节 | 含义 | 为什么不能省 |
| --- | --- | --- |
| 源视频 | 拍摄时的名义帧率 | 60/120fps 只是采样间隔，**不自动消除运动模糊** |
| 实际解码 | 浏览器真正解出来几帧 | 掉帧与时间戳回绕都发生在这里（F-011 就是回绕） |
| 姿态推理 | 真正进模型的帧 | 实时预览**允许丢旧帧**压延迟 ⇒ 它与上面两个都不等 |
| JPEG 候选 | 关键帧缓存里的图 | 现在是**每 3 帧一张**，30fps 下约 **100ms 间隔**（F-028） |

**导入视频必须按可控的解码步长逐步处理**，不能复用它实时播放时"恰好处理了哪些帧"
—— 那取决于机器当时的负载，**同一支素材跑两次能拿到不同的帧集合**，而 P1 的标注
真值要对着一份可复现的观测。

**实时预览的丢旧帧是正确行为**，不要为了可复现把它去掉：要的是把两条路径分开，
而不是让导入去将就实时。

### 1.6 两条不可越的线

1. **单目二维的能力边界**：不提发力大小、肌肉紧张、足底承重、力量传递效率、精确拍面朝向。
   二维投影随**机位**变化，所以每个指标都要声明**允许机位**与质量要求，
   不能用一个全局"骨架可见"许可所有精细结论。
2. **模型不是真值**：视觉模型负责提点、时序模块负责找阶段、比较模块负责算差异，
   大模型只组织解释与推荐**已审核**训练项。它可以提出候选问题，**不能生成测量值**，
   也不能把未审核的猜测升格为确定纠错。

#### 每个指标单独写出"何时不能判断"（评审 §7）

上面第 1 条那句"不能用一个全局'骨架可见'许可所有精细结论"，展开成逐指标的一句。
**这张表是 P4 的依据** —— 每想新增一个能力，先要能写出它落在哪一行、
以及那一行的"何时不能判断"是否真被解掉了。

| 要回答的问题 | 首版能做的观测 | 何时**不能**判断 |
| --- | --- | --- |
| 小臂有没有明显屈伸 | 二维肘角曲线、阶段内变化幅度与时间 | 遮挡、运动出平面；**不能**推断小臂发力大小 |
| 大臂是否抬起较多 | 肘相对肩/躯干的位置变化、上臂投影角 | 不能据此断言肌肉僵硬或代偿原因 |
| 是否前倾/起伏明显 | 躯干投影倾角与髋高度变化 | 正面**看不清**前倾；髋位置 ≠ 重心/足底承重 |
| 还原是否跟上下一板 | 随挥到准备区/下一板的时间关系 | 分段失败时；原地停留 ≠ 功能上准备好了 |
| 手腕是否相对前臂改变 | 合适视角下的投影夹角变化 | 握拍遮挡、轴向旋转、手点误检；**不把小臂旋转误判成手腕屈伸** |
| 拍面朝向是否合适 | 后期做投影姿态或经验证的 3D 估计 | 仅手部骨架**不足**；背面/侧缘、运动模糊可能不可判 |
| 击球是否偏早/偏晚 | 后期研究接触相对来球阶段的关系 | **腕峰不能替代接触**；单张姿势照不能决定时机 |
| 腿髋躯干小臂是否协调 | 仅做可见的粗粒度时序比较 | **不**输出传力效率、肌肉激活、地面反作用力 |

### 1.7 界面分两层（评审 §9）

- **练习中**：每组**最多一条**优先提示（保留"一次只注意一个点"的习惯）；
- **练习后**：多维度详细对照，**包含不可判项**。

分析全面 ≠ 同时播报多个纠正动作。复查页提供同阶段的用户/参考并排图、对应关键点、
短片回放、曲线与问题证据；**二维叠加只对相容视角展示** —— 不强行配准不同机位
制造"看似精确的红绿重合图"。

| 要素 | 状态 |

| 逐板数值（每板各自的测量值，缺失带原因） | ✅ 已做 |
| 阶段转变时间线（引拍／前挥／还原开始、本板闭合，各带时刻） | ✅ 已做 |
| 证据包 `limitations` **原样**显示（模型只知道这些） | ✅ 已做 |
| 关键帧标出「属于哪一板、距事件偏了多少」 | ✅ 已做 |
| 短片回放（按板定位视频片段） | ✅ 已做（导入视频；摄像头链路的说明见下） |

### 1.8 标注纪律：真值怎么来才算数（评审 §5.4 / §10 / §12.7）

P1 的全部价值取决于这批标注**是不是干净的**。下面五条是**开始标之前**就要定下来的
规矩，不是"标完再看要不要补" —— 划分一旦泄漏，事后补不回来。

1. **标注者不先看算法输出**。只看原视频与标注规则。先看过检出结果再标，
   标出来的是"我同意算法"，不是"我看见的事实"。
2. **按日期/拍摄批次留出测试集**；若要声称"对不同人也有效"，必须**按人**留出。
3. **参考示范、校准集、测试集彼此独立**；**禁止把同一段视频的相邻帧分到不同集合**
   —— 相邻帧近乎重复，分到两边等于把测试集抄进训练集。
4. **人工也判不了的片段保留"不可判"标签**，不强行投票制造真值。
5. **报告各类样本数**（正常/异常/遮挡/走动）；没有标的那一类**不能算通过**。
6. **工程测试与真实识别质量分开报告**（评审 §12.7）。"660 项测试全绿"是关于
   **代码正确性**的证据，**不是**关于"识别准不准"的证据 —— 两栏必须分开写，
   否则前者会被当成后者读。

**为什么单列一节**：这五条与"跑几条命令导出观测"是两类事 —— 后者可以替你做，
前者决定前者有没有意义。见 P1。

## 4. 最小验证实验：先找瓶颈，再决定投多少

用同一批 6–10 段视频分四组跑（评审 §11）：**A 当前基线 / B 事件正确 / C 标准正确 / D 可自动化**。

判断规则：

- B 明显好于 A → 先做**事件与选帧**；
- C 明显好于 B → 投入**标准建设**；
- D 明显落后于 C → 优化**感知与时序**；
- 连 C 都给不出可信建议 → 才去怀疑**模型能力**或收窄任务。

**这样做的意义**：避免把所有问题都归因于"模型不够强"。
本次会话已经证明这个担心是实的 —— 用户最初以为"模型返回的信息太少"，
而实测里 R2/R3 让**图片标签全丢、数量少发 2/3**，那是上游的问题，不是模型的。

| ITTF [正手](https://www.ittfeducation.com/how-to-play-table-tennis-forehand-drive/) / [反手攻球](https://www.ittfeducation.com/how-to-play-table-tennis-backhand-drive/)教学 | 官方有分技术类型的教学示范 | 建立术语、阶段、教学要点与参考视频目录 | 页面**不是**可执行的角度阈值 |
| [Bańkosz & Winiarski 2020](https://www.jssm.org/volume19/iss1/cap/jssm-19-138.pdf) | 正手上旋对上下旋来球；运动学采集 + **压电触球识别** | 标准需按来球条件划分，并允许不同的协调方式 | 上旋拉球的数值**不能**当定点正手攻球的合格线 |
| [Kulkarni & Shenoy 2021](https://arxiv.org/abs/2104.09907) | 14 名专业球员、11 类动作、22111 段视频；二维姿态 + TCN | 将来动作分类与时序编码的参考 | 99.37% 的**分类**准确率 ≠ 错误诊断准确率 |
| [Martin 等 2021](https://arxiv.org/abs/2109.14306)（TTStroke-21） | RGB + 光流 + 姿态三路融合做细粒度分类与分段 | 借鉴多信号阶段识别 | 没有因此得到每个关节的"对/错"教练标签 |
| [TTNet 2020](https://arxiv.org/html/2004.09927v1) | 120fps；球检测、分割、球台反弹与触网事件 | 后续球轨迹与快速事件的研究底座 | 现成事件头**不是**人体动作评分器 |
| [Tumpach & Kán 2023](https://arxiv.org/abs/2303.15259) | 用关键帧对应约束的动态规划做时间对齐；提醒保留有意义的竖直方向信息 | 阶段锚定的时序比较（P3） | 不受限的时间变形**会掩盖**真实的节奏错误 |
| [MediaPipe Pose](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker) / [Hand](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker) | 33 个身体点 / 21 个手部点，可输出估计的世界坐标 | 保留为第一版测量底座 | 模型估计的 3D **不等于**标定过的真实三维测量 |
| [Sports2D](https://github.com/davidpagnon/Sports2D) | 二维姿态/角度；**明确强调运动平面与拍摄方向的限制** | 离线算法比较与导出工具 | **机位不同的数据不能直接按二维角度严格比较** |
| [Pose2Sim](https://github.com/perfanalytics/pose2sim) | 多机位标定、同步、三角化与运动学流程 | 中后期做更可靠的三维参考序列 | 多加一台相机但**不标定、不同步**，不会自动得到可靠 3D |

检索中另见到 2026 年 OpenPose + YOLO 的多维评价论文，但**全文访问失败** ⇒
**不采用**其具体阈值与准确率作为依据。

**一条结论**：现有公开资料里**没有**能直接导入、覆盖个人纠错需求的完整"通用标准动作库"。
这正是 §1.4 决定"不做通用标准库、改做混合标准包"的依据 —— 不是偏好，是查过之后的结论。
