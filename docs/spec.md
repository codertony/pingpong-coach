## 用户目标

练习定点正手攻球时，不再手工录制、裁剪、上传和追问；几秒内得到**下一组能执行的一条提示**。

## 三种能力必须分开验收

这三项**不能**互相代替：

1. **测量能力**：关键点、轨迹和角度是否反映画面中实际可见的变化。
2. **反馈能力**：程序是否能自动给出及时、可复查、不过度推断的提示。
3. **训练效果**：用户按提示练习后是否改善，关闭提示后是否仍有保留。

能画出骨架只满足第一项的一部分。大模型给出通顺解释也不代表第三项成立。

## 首版范围

**做：**

- 定点正手攻球、单人、固定机位
- 持拍侧肩肘腕的二维关键点、质量检查、挥拍自动分段
- 第一批特征：肘角变化范围、肘相对躯干位移、`return_after_wrist_peak_ms`、组内一致性
- 一组一次多模态模型调用，返回一条观察 + 一条短提示
- 关键帧与数值复查、用户评价、样本导出
- 未审核目标走本地规则即时提示，不阻塞采集

**不做：**

- 由骨架推断肌肉紧张、发力大小、足底承重、精确拍面、毫秒级传力顺序
- 多 Agent 编排、逐帧语言模型描述、多轮自我审查
- 账户、订单、组织权限、复杂训练计划 CRUD
- 自动动作类型分类（用户继续手动选择动作）
- 完整视频录制与回放（P2）
- 同机位下同时维护两套实时视觉引擎

## 首版环境假设

- 单人、固定摄像头、持拍侧肩肘腕可见
- 动作与机位由用户选择
- 电脑 Chrome/Edge 配本机摄像头，或导入手机拍摄的清晰视频
- P0 目标：实际处理频率约 25 FPS 以上

## 已知限制（必须向用户如实呈现）

| 限制 | 后果 |
| --- | --- |
| 单目二维骨架 | 无法判断肌肉紧张、发力大小、足底承重、力量传递效率 |
| 锚点为腕部速度峰值 | **不是**已确认的击球时刻；指标命名为 `return_after_wrist_peak_ms` |
| 二维角度依赖拍摄方向 | 斜侧机位不能当作解剖角度 |
| 有效帧比例不足 | 只报观察，不做精细判断 |
| 尚无已审核参考片段 | `return_to_ready_zone` 规则保持 `observation_only`，不输出"合格" |
| 无持久化 | P1 反馈保存在浏览器；进程重启后历史丢失 |
